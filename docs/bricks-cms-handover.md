# WordPress + Bricks CMS 引き継ぎ仕様

BricksはWordPressに導入して使うテーマビルダーです。現段階ではWordPress本体、ホスティング、Bricksライセンス、管理者アカウントが未契約のため、現在のサイトは静的な仮データを `src/data/content.json` から生成しています。契約・開設後は、以下の構成で差し替えます。

## 投稿タイプ

| 投稿タイプ | 用途 | 必須フィールド |
| --- | --- | --- |
| お知らせ | 最新情報の一覧・詳細 | タイトル、公開日、本文、アイキャッチ、カテゴリー |
| キャンペーン | トップ上部のバナー・一覧・詳細 | タイトル、公開日、概要、アイキャッチ、遷移先URL、外部リンク指定、掲載状態 |
| 店舗 | 全店舗一覧・店舗別詳細 | 店舗名、固定スラッグ、住所、郵便番号、電話番号、営業時間、定休日、アクセス、GoogleマップURL、店舗別メニュー、SNS／LINE URL |

キャンペーンの最上位バナーは、`掲載状態` が公開、かつ公開日が新しい順に最大3件をBricksのQuery Loopで表示します。カード全体のリンクは、内部記事ではパーマリンク、外部誘導ではカスタムフィールド「遷移先URL」を使います。現行の1件目にはユーザー指定の `https://www.yakiniku-like.com/2026/08/25/yoru-lunch-bangohan/` を設定しています。

## ブロック配置

トップページは、(1) ヒーロー、(2) キャンペーンカード3枚、(3) 左にキャンペーン情報・右に最新情報の2カラム、(4) 看板メニュー、(5) コンセプト、(6) 店舗・メニュー、の順です。キャンペーンと最新情報はヒーロー直下に置きます。

「コンセプト」は横長の料理写真に文字を重ねるヒーロー、「店舗・メニュー」は余白のある2カラム店舗一覧で、各店舗に「店舗情報」「メニュー」のボタンを置きます。これはご提供の参考画面の情報順・余白・見せ方を忍鬨のロゴ、料理写真、店舗データで再解釈したものです。参考サイトのロゴ・写真・コードは移植しません。

## 店舗SEOを維持する実装

店舗はWordPressのカスタム投稿タイプ `store` として登録し、現在の8スラッグを変更せずに使います。`/stores/{slug}/` のパーマリンク構造を維持し、既存URLを変える必要がある場合だけ、旧URLから新URLへ301リダイレクトを設定します。全店舗一覧は `store` のQuery Loop、店舗詳細はBricksのSingleテンプレートで生成します。

各店舗詳細テンプレートでは、画面に表示している店舗名・住所・電話番号・営業時間・定休日・アクセス・メニューだけをカスタムフィールドから読み込みます。同じ値から `Restaurant` JSON-LD と `BreadcrumbList` を1ページにつき各1件出力します。自己サイトで取得・管理していない第三者の評価・口コミは `aggregateRating` や `review` に入れません。`name`、`address`、`telephone`、`openingHoursSpecification`、`url`、`image`、`menu`、`hasMap` を店舗データに応じて出力し、未確認の座標は出力しません。

公開時はWordPressのサイトURLを正本として、各店舗のcanonical、OGP URL、sitemapを同じ本番HTTPSドメインで統一します。Bricks側の公開後には、旧静的サイトの全8 URL、`/stores/`、`/sitemap.xml`、`/robots.txt` をHTTP 200で取得できることを検証します。

## 移行時の注意

WordPress本体とBricksライセンス、ホスティング、実公開ドメインが準備できたら、管理者URL・REST APIの可否・編集権限を共有してください。接続情報はメッセージに書かず、安全な入力フォームで共有します。実ドメイン確定後はcanonical、OGP URL、Restaurant JSON-LDのURL、sitemap.xmlをそのドメインで再生成・検証します。
